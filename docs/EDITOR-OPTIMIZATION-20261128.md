## Corrección aprobada: coherencia de repertorios en Ajustes
La función anterior generaba en memoria «Repertorio completo» aunque no existiera en el Editor ni Drive. Se elimina la generación; LIVE y Ajustes muestran únicamente repertorios reales, conservando canciones, orden y listas vacías válidas. No se modifica la biblioteca persistente. Una selección antigua del repertorio virtual se resuelve con el primer repertorio real; una lista real del mismo nombre no se elimina. Pruebas unitarias y de navegador incluidas. Publicación exclusivamente Web QA; compilaciones nativas diferidas hasta finalizar el ciclo. Aceptación física pendiente.

## Corrección previa al Editor: arranque directo en Inicio
El usuario detecta pantalla blanca y destello LIVE antes de Inicio. Aprobada corrección prioritaria Web QA. El documento de entrada conserva fondo oscuro y título; la entrada LIVE oculta su interfaz desde el script crítico anterior al marcado para rutas HOME y callback OAuth. Durante carga se muestra estado breve y oscuro, no el contenido de interpretación; se retira tras abrir HOME o Ajustes. Acceso directo LIVE conserva su funcionamiento; no se cambia la autorización ni la biblioteca. Prueba Chromium con carga retardada en las dos entradas y acceso directo. Las apps nativas se mantienen sin recompilar hasta el final del ciclo. Aceptación visual real pendiente.

## Refinamiento de arranque aprobado: fondo continuo y fundido de entrada
El usuario confirma que LIVE ya no aparece durante el arranque y que el enlace directo muestra la pantalla oscura de carga. Prefiere fondo #03080D sin título ni texto durante la inicialización y aparición progresiva del contenido HOME (opacidad 0→1, 400 ms, ease-out, sin desplazamiento ni espera artificial). El fondo del diálogo no se anima; el fundido es exclusivo del arranque en HOME, no de volver desde Ajustes ni del callback OAuth. Se respeta prefers-reduced-motion y se conserva el mensaje de error de inicialización. Pruebas de navegador ampliadas. El navegador puede mostrar su propio color antes de recibir HTML; no se promete controlar ese intervalo. Se publica solo Web QA tras pruebas; nativas diferidas.
