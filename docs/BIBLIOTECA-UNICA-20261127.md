# v8.2 QA — biblioteca lógica única (27/11/2026)
Web móvil/escritorio, Windows, Android e iOS comparten el mismo cliente OAuth del Worker, la misma cuenta Google y el historial Drive appDataFolder `midi-hud-test-sync-v1`. Las cachés físicas permanecen aisladas por dispositivo; no son fuentes independientes. Los perfiles nativos Windows/Android conservan sus claves históricas dentro de orígenes QA dedicados; iOS y web conservan su prefijo existente.
La autorización nativa utiliza el navegador del sistema y una prueba de un solo uso, sin transmitir tokens Google al WebView. El proxy nativo permite únicamente rutas del Worker y el Worker limita Drive a los endpoints existentes. Producción web mantiene su comportamiento. En HOME se aplica automáticamente una descarga compatible con el motor; LIVE conserva la interpretación y el Editor conserva borradores. Si el servidor o Google no están disponibles, se trabaja con la última copia local, sin subir automáticamente los datos de ejemplo.
Aceptación pendiente: CI, despliegue del Worker, builds nativos, autorización de la misma cuenta en los cuatro clientes y verificación bidireccional física de repertorios. No declarar sincronización validada hasta completar esta prueba. No migrar ni borrar historial automáticamente.

Sincronización automática obligatoria en QA; la antigua preferencia off se normaliza a on. Una caché sin base verificable no puede sobrescribir Drive. Si no existe biblioteca remota, la primera publicación exige confirmación explícita desde el dispositivo correcto. La aceptación se prueba con cuatro clientes simulados y posteriormente con dispositivos físicos.
